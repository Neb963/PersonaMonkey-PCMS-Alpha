## What changed

| Area | Files |
|---|---|
| Manifest (A030-01) | `extension/manifest.json` declares `sandbox.pages` = `pcms/sandbox/controller.html`, `pcms/sandbox/module-ui.html` and sets **only** `content_security_policy.sandbox`, so extension pages keep Firefox's MV3 default CSP. `strict_min_version` stays `153.0` (ADR-003 open decision, default b). Derivative override recorded in `docs/upstream/import-manifest.json`. |
| Sandbox CSP (A030-01) | One shared policy (ADR-003 §1 option 1): `sandbox allow-scripts` without `allow-same-origin`; `default-src`, `connect-src`, `frame-src`, `child-src`, `worker-src`, `object-src`, `media-src`, `manifest-src`, `base-uri`, `form-action` all `'none'`; scripts `'self' 'unsafe-eval'`; styles, fonts and images only from the extension (`img-src 'self' data:`). Every P004 network and frame denial is kept. |
| Browser floor (A030-01) | `extension/pcms/runtime/browser-floor.js`: Firefox major ≥ 154, declared sandbox, safe sandbox CSP and a proven isolated frame give `AVAILABLE`; otherwise `UNAVAILABLE` with a reason and the message "Requires Firefox 154+". Detection is memoized and never throws; nothing is loaded below the floor. |
| Controller page (A030-02) | `controller.html` loads a classic `controller.js`, generated by `tests/pcms/p030/controller-bundle.mjs` from the P004 `protocol.js` and `controller-runtime.js` (still the single source of truth; a test fails when the bundle is stale). `module-ui.html` is an inert placeholder for P033. |
| Frame factory (A030-02/03) | `extension/pcms/background/sandbox/frame-factory.js` creates `sandbox="allow-scripts"` iframes in the background document per module generation, rejects duplicate generations, verifies isolation, handles load timeout/error, and disposes one or all frames. |
| Module runtime (A030-03) | `module-runtime.js` takes a `support` option, refuses activation with `PCMS_MODULE_RUNTIME_UNAVAILABLE` below the floor, and releases a frame lease on activation failure and on drain. |
| CI | `firefox.yml` runs `test:p030` and `firefox:packaged:p030`, uploads `firefox-packaged-p030`, and bounds/retries the runtime-library apt step (two runs had hung there on the mirror). |

## Pinned-build observations encoded as regressions

1. `runtime.getBrowserInfo().version` is `"154.0"` on the 154.0b10 build, so the floor compares majors only (`browser-floor.test.mjs`).
2. A declared sandbox page has an opaque origin and cannot load ES module scripts, hence the generated classic bundle (`controller-bundle.test.mjs`).
3. A tightening meta CSP in the sandbox page was not enforced (an extension image loaded under `img-src 'none'`), so the page relies on the manifest policy alone (`manifest.test.mjs`).
4. Firefox attributes `postMessage` to the calling realm, and the controller accepts its bootstrap only from its parent. A tab therefore cannot bootstrap a frame hosted by the background page. The packaged run proves isolation of both pages and the ignored foreign bootstrap in the background document, and proves execution with an extension page as host. Background-hosted execution driven by product host code lands with P031's live wiring.
