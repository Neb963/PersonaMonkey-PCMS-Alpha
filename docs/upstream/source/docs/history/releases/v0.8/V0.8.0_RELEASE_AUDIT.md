## Defects and fixes

| ID / severity | Reproduction and root cause | Fix, regression, verification |
|---|---|---|
| PM-SEC-01 — P1, fixed | At the starting candidate, content-script contexts could reach privileged runtime messages and PCMS event ports. Sender checks had been removed from the background boundary. | Commit `82f4457`; restore extension-page validation, keep only the narrow userscript/automation signals available to content contexts; `background-smoke.test.mjs` and `npm test` pass. |
| PM-STATE-01 — P1, fixed | Read Options snapshot at revision N, commit PCMS route change N+1, then save the old snapshot: the background accepted a full snapshot without revision metadata. | Commit `82f4457`; require metadata for `SAVE_STATE`. Regression asserts `STATE_CONFLICT` and preserves the newer route; `npm test` passes. |
| PM-PERSONA-01 — P2, fixed | Delay identity update/removal events around another mutation: handlers read/write stale full snapshots, allowing stale metadata or Persona resurrection. Without `contextualIdentities.get`, an event payload could be stale. | Commit `80ae567`; queue changes through `mutateState`, ignore unmanaged/missing identities, and query the current identity before accepting an update. Delayed-event, deletion, and no-`get()` regressions pass. |
| PM-GM-01 — P1, fixed | Dispatch `GM_xmlhttpRequest` or `GM_download`, hold the first state read, then abort before it resolves. The old code had not registered its controller, so the operation could still start network or download work. | Commit `9e5fb41`; register controllers synchronously and check cancellation after awaited state/cookie reads. Immediate-abort tests verify no fetch/download starts; focused tests and `npm test` pass. |
| PM-NATIVE-01 — P2, fixed in unit coverage | Cancel during relay connection/SOCKS negotiation or an HTTPS response read. The old active record could lack the in-progress socket or retain the raw socket after TLS wrapping. | Commit `9e5fb41`; register before setup, make connect polling cancellable, track the TLS socket before handshake, and send a separate `cancel_fetch`. Controlled connect, SOCKS, HTTP, and wrapped-HTTPS cancellation tests pass. Real TLS/native-host behavior remains unverified. |
| PM-GM-02 — P2, fixed | Start a GM download and abort while Firefox is creating its download entry, with `browser.downloads.cancel()` rejecting. The old code swallowed cancellation errors and returned a successful abort acknowledgement even though the download could remain active. | Commit `e0e4cf7`; keep the pending download promise, deduplicate concurrent cancel calls, propagate Firefox cancellation errors to the abort response and userscript `onerror`. `gm-security.test.mjs` reproduces the previous false success, verifies the pending-ID failure path, and checks the injected error callback. `npm test` passes. |
| PM-POLICY-01 — P2, open release gap | For a managed Persona explicitly assigned Direct, call GM XHR on a permitted public URL that redirects to a blocked domain or local address; likewise use a redirected GM download. The initial URL is checked, but direct `fetch` follows redirects and `downloads.download` follows its URL without rechecking each destination. The background exempts extension-origin requests, so its ordinary webRequest policy path does not supply a second check. | No fix in this candidate. Expected: reject before requesting any disallowed redirect destination while preserving the documented Direct bypass for routing. Add a real Firefox negative test with a controlled redirect endpoint, including GM XHR and download, then implement and retest per-hop enforcement or a documented fail-closed behavior. No P2 exception has been approved. |

The open PM-POLICY-01 finding is based on the concrete source path; this environment could not run the real browser reproduction. Protected Mullvad fetch redirects are rechecked by the native host, but that does not close the explicit Direct path.
