# PersonaMonkey v0.6.0

v0.6 makes workflows portable, observable and practical to operate while preserving the routing and security architecture established in v0.4/v0.5.

## Implemented workflow usability

- Workflow duplication creates fresh workflow and step IDs.
- Steps can be reordered explicitly and continue to execute sequentially.
- Validation reports all actionable errors before Run, including missing/blocked personas, missing/disabled routes, bad URLs, userscript assignment problems, invalid completion settings and retry configuration.
- Retry delay is configurable per step and persisted without changing the state schema version.
- Activity persists and displays per-step progress, task totals, retry state, attempt history, retry timing and historical persona/route/completion snapshots for new jobs.
- Cancellation closes only job-owned tabs, interrupts retry delays, persists terminal state and renders the Stop/stopping transition without stale-refresh regressions.
- `Persona.complete()` signal mode can complete a task as soon as the valid userscript signal arrives after navigation begins; it no longer waits for a later page-load-complete event.

Steps execute sequentially in workflow order. URLs inside a step may execute concurrently according to that step's concurrency and the extension-wide automation caps. A dedicated orchestrator regression test proves the second step does not prepare or navigate until the first step finishes.

## Portable workflow packages

Canonical distributable format: **ZIP**, normally named `*.personamonkey.zip`.

A package contains:

- `manifest.json` — versioned package/workflow definition;
- `userscripts/*.user.js` — every userscript referenced by the packaged workflow.

The manifest uses portable persona slots (`personaKey`) rather than Firefox `cookieStoreId` values. Import is deliberately two-stage: PersonaMonkey first validates and previews the package, required userscripts and compatible persona mappings; the user then maps each slot to an existing managed persona and confirms the import.

Userscripts use package-local keys. Import parses metadata, validates grants, verifies a declared SHA-256 when present, reuses an identical installed script when possible, otherwise imports a conflict-safe local copy, and automatically assigns the resulting script to every mapped persona whose workflow steps reference it.

Workflow packages never carry route credentials, WireGuard keys, cookies, GM storage or other browser/persona data. Import never starts the workflow automatically.

## Package safety

The ZIP layer rejects:

- absolute, traversal or backslash paths;
- duplicate archive paths;
- encrypted entries;
- unsupported compression methods;
- CRC or size mismatches;
- excessive entry counts and uncompressed payload sizes.

PersonaMonkey exports stored ZIP entries for maximum portability. Import also supports standard DEFLATE entries when the runtime provides `DecompressionStream('deflate-raw')`.

The authoring contract is documented in `docs/WORKFLOW_PACKAGES.md` and the machine-readable schema is `docs/personamonkey-workflow-package.schema.json`.

## Real userscript-driven example

The repository contains `examples/workflow-packages/mullvad-signal-check/`, a real two-step package rather than an `example.com` placeholder.

It requires one `protected` persona slot and includes a `@grant none` userscript that calls `Persona.complete()` on:

1. `https://am.i.mullvad.net/`
2. `https://ipv4.am.i.mullvad.net/`

CI validates the package source and builds `mullvad-signal-check.personamonkey.zip` as a downloadable artifact.

## Regression and release gates

v0.6 adds or expands coverage for:

- ZIP writing/parsing, CRC checks and unsafe paths;
- package export → inspect → persona mapping → userscript import/reuse round trips;
- workflow duplication, step movement, aggregate validation and route readiness;
- strictly sequential multi-step execution;
- MAIN-world `Persona.complete()` bridge generation and execution;
- signal completion without a later page-load-complete event;
- persisted progress, retry and cancellation behavior;
- browser-level duplication, validation, package export/import preview and confirmation, retry-delay persistence, progress/attempt rendering and Stop behavior;
- building the real Mullvad signal workflow package artifact.

The existing routing, privacy, native Mullvad, GM security, storage compatibility and userscript regression suites remain required. Validation, packaging and artifact upload are blocked when the browser interaction gate fails.

## Compatibility and non-goals

- Gecko ID remains `persona-route-manager@local`.
- Persisted state schema remains version 2.
- Existing v0.3/v0.4/v0.5 workflows normalize forward without destructive migration.
- Protected personas remain fail-closed; no direct fallback is introduced.
- Native Messaging transport and route semantics are unchanged.
- No new daemon or database is introduced.
- No Perchance-specific production workflow is bundled in this milestone.
