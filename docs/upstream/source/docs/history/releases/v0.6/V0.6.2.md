# PersonaMonkey Route Manager v0.6.2

> **Superseded cookie-enumeration note:** the v0.6.2 interpretation of Firefox `firstPartyDomain: null` below was incorrect. Firefox uses `firstPartyDomain: null` as the `cookies.getAll()` wildcard for all first-party domains, while `partitionKey: {}` requests both partitioned and unpartitioned storage. v0.6.3 corrects the implementation and tests. See `V0.6.3.md` and `DATA_PORTABILITY.md` for the current contract.

v0.6.2 is the release that introduced the dedicated Cookies workspace and persona UI improvements. Its cookie-enumeration fix was incomplete and is superseded by v0.6.3.

## Cookie listing attempt (superseded by v0.6.3)

v0.6.2 changed cookie enumeration to query only by the selected contextual-identity `storeId`. The release was based on an incorrect test model that treated `firstPartyDomain: null` as a restrictive equality filter.

Real Firefox semantics differ: `firstPartyDomain: null` means all first-party domains for `cookies.getAll()`, and `partitionKey: {}` is required to enumerate both dynamically partitioned and unpartitioned cookie storage. v0.6.3 restores those two wildcard selectors while retaining the selected `storeId` as the persona boundary.

Individual mutations in v0.6.2 already carried first-party-domain and partition metadata when the cookie had it; that behavior remains in v0.6.3.

## Dedicated Cookies workspace

Cookie operations are organized under their own **Cookies** tab. Each managed persona can open it directly from **Profiles → Cookies**.

The workspace supports:

- persona selection with Firefox contextual-identity icon/color metadata;
- cookie filtering;
- create/edit/delete;
- select-visible and selected-cookie operations;
- clear all in one persona;
- clear a domain plus subdomains in one persona;
- copy selected cookies to another managed persona;
- versioned plaintext `*.personamonkey-cookies.json` export/import;
- merge or replace import modes.

Direct cookie files are intentionally plaintext and are labeled as sensitive because cookie values can be live session credentials. Encrypted complete/selective PersonaMonkey backups remain the protected-at-rest format.

## Profile-row shortcuts

Managed persona rows expose four direct actions:

- **Edit** — routing/domain policy;
- **Cookies** — dedicated cookie workspace;
- **Test** — egress test;
- **Export** — portable non-sensitive persona export.

The quick persona export includes the persona policy plus required route/userscript dependencies, redacts route credentials, and excludes cookies. Use Data & backup for encrypted/sensitive exports.

## Persona appearance

The Profiles and Cookies UI uses Firefox contextual-identity metadata when available:

- `iconUrl` for the actual container icon;
- `colorCode` / contextual color for the persona color;
- icon/color names as fallback metadata.

## Compact options shell

The options header is reduced to the product name and current protection status. Descriptive copy has moved into the individual sections, leaving more vertical space for actual controls and tables.

## Testing

The v0.6.2 browser cookie gate covered cookie workspace and persona-isolation flows, but its `getAll()` stub modeled Firefox first-party-domain semantics incorrectly and did not model dynamic partition enumeration. v0.6.3 replaces that assumption with a regression containing first-party-isolated, dynamically partitioned, and unpartitioned cookies.

## Compatibility

v0.6.2 did not change:

- Gecko extension ID `persona-route-manager@local`;
- persisted state schema version 2;
- native Mullvad protocol;
- fail-closed routing semantics;
- workflow or userscript package contracts.
