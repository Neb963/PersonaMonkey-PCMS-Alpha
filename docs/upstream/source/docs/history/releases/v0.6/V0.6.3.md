# PersonaMonkey Route Manager v0.6.3

v0.6.3 is a corrective Firefox/LibreWolf cookie-visibility release built on the v0.6.2 Cookies workspace.

## User-reported failure

v0.6.2 could still show **0 cookies** for a managed persona even while that Firefox/LibreWolf container remained logged into websites across browser restarts. The problem was cookie enumeration, not loss of browser session data.

## Root cause

Firefox exposes two independent cookie-isolation dimensions to WebExtensions:

1. **First-party isolation** (`firstPartyDomain`). For `browser.cookies.getAll()`, `firstPartyDomain: null` requests cookies from every first-party domain. On profiles with first-party isolation enabled, omitting this field can make the query fail.
2. **Dynamic storage partitioning** (`partitionKey`). Without a partition selector, `getAll()` enumerates unpartitioned storage. `partitionKey: {}` requests both dynamically partitioned and unpartitioned cookies.

v0.6.2 modeled the first rule incorrectly and queried only by `storeId`. That was insufficient for hardened Firefox/LibreWolf configurations and did not explicitly enumerate dynamic partitions.

## Fix

PersonaMonkey now lists cookies for one contextual identity with:

```js
browser.cookies.getAll({
  storeId: personaCookieStoreId,
  firstPartyDomain: null,
  partitionKey: {}
})
```

The persona's exact `cookieStoreId` remains the isolation boundary. The wildcard values only enumerate all Firefox cookie partitions inside that one store.

Set/remove operations continue to use the exact `firstPartyDomain` and `partitionKey` from each cookie when Firefox exposes them, so mutations target the same cookie identity that was listed.

## Regression-first verification

The correction was developed regression-first.

- `d7bd6b9` changed the cookie-service regression to model Firefox first-party isolation and dynamic partitioning. It intentionally failed against the v0.6.2 service because the service omitted `firstPartyDomain`.
- `7204ffc` changed the service to enumerate with `storeId`, `firstPartyDomain: null`, and `partitionKey: {}`. All 29 extension regression files then passed.
- `e6fffc4` corrected the real-browser data-management stub and added a dynamically partitioned cookie alongside ordinary cookies. The browser gate requires all of them to appear in the selected persona and verifies the exact enumeration arguments.

Automations/package/diagnostics browser coverage remains unchanged and must also stay green.

## Compatibility and security

v0.6.3 does not change:

- Gecko extension ID `persona-route-manager@local`;
- persisted state schema version 2;
- native Mullvad protocol or helper contract;
- workflow/userscript package formats;
- fail-closed routing behavior;
- protected-persona direct-fallback rules.

No cookie is copied, cleared, edited, or deleted across contextual identities unless the user explicitly selects a cross-persona copy operation.

## Remaining validation boundary

The automated browser gate now models the relevant Firefox semantics rather than the incorrect v0.6.2 model. It is still a deterministic WebExtension stub, not an installed LibreWolf process with the user's real cookie database. Real LibreWolf verification remains the decisive release check for the original report.
