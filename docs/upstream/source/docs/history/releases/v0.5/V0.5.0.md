# PersonaMonkey v0.5.0 hardening plan

v0.5.0 is a stability and observability release. It deliberately avoids adding new workflow semantics or Perchance-specific behavior until the existing routing and automation foundation is easier to reason about and diagnose.

## Release goals

1. **One Automations controller**
   - Replace the v0.4 compatibility `MutationObserver` workflow controller with a deterministic event-delegated controller.
   - No DOM mutation observer is allowed in the workflow editor.
   - The controller owns workflow selection, creation, editing, validation, save, run, delete, add/remove step, and completion-mode UI behavior.
   - Existing persisted v0.3/v0.4 workflows remain readable.

2. **Actionable diagnostics**
   - Activity shows workflow, persona/container, assigned route, completion mode/value, tab id, attempts, timestamps, elapsed time, and terminal errors per task.
   - Activity shows the current fail-closed security state, last proxy error, and last blocked request near job history.
   - Diagnostic presentation must not expose route passwords, WireGuard keys, or other secrets.

3. **Browser-gated UI stability**
   - Keep the real-browser Automations smoke test as a packaging gate.
   - Extend smoke coverage to diagnostics rendering, completion-mode controls, add/remove step, save, and new-workflow editing.
   - Release artifacts are produced only after regression tests, browser UI smoke, validation, and build all pass.

4. **Release usability**
   - Build one extension-only XPI plus SHA-256 checksum.
   - Keep the stable Gecko extension id `persona-route-manager@local` so upgrades retain local storage.
   - Provide the exact CI-produced XPI as the downloadable test artifact.

## Non-goals

- No new daemon, database, or protocol.
- No weakening of fail-closed routing.
- No new Perchance production workflow.
- No Chrome product support; Chrome is used only as one browser-level DOM regression environment.
- No state-schema migration unless a blocker is found.

## Release gate

A v0.5.0 XPI is shippable only when the exact release commit passes:

- extension regression suite;
- Automations browser interaction smoke;
- release metadata validation;
- deterministic extension package build;
- artifact upload and downloaded-XPI checksum verification.
