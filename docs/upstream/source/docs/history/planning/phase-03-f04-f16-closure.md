## F-04 — silent management collection loss

- **Status:** fixed and locally verified; synthetic final-build Firefox acceptance passed for the Management and Integration paths. Full Phase 08 release acceptance remains open.
- **Root cause:** both generic response sanitizers cut arrays/objects at 100, successful oversized responses returned a truncated placeholder, and some userscript/workflow projections cut accepted data before sanitization. The management console consumed only a single response.
- **Remediation:** complete secret-safe projections or typed oversize errors, deterministic snapshot-bound pagination on all five list commands in both APIs, bundled console page traversal, full workflow projection/unchanged-update preservation of stored URL secrets, and explicit oversized batch-row outcomes.
- **GitHub commits:** `f605b11d52d5ac1f28d31e484610ae771c45ce9c`, `3cd8e93374fb531e14d1c43f6e16275a683c86a3`, `fa11f5559c350594891dd5c3992d23f067e2a354`, `b5c666a3200742995e0eabf8b100d8d851084101`, `824502ff8dc5abc4af80bdf341187e3c407c6470`.
- **Regression tests:** `pcms-protocol-hardening.test.mjs`, `pcms-pagination-cardinality.test.mjs`, `pcms-events-client.test.mjs`, `management-integration.test.mjs`, and `pcms-secret-projection.test.mjs`. They cover 150 Personas through each contract, all five paged lists, 150/200 workflow steps, 150/500 URLs in a step, secret-safe unchanged updates, invalid/stale cursors, 200 batch outcomes, and an applied but oversized batch item.
- **Browser evidence:** Firefox 157.0 kept the final v1.0.0 XPI (SHA-256 `f6f05ace0214a1d72539f8e88eee799e0155025882abd0940172db2706472025`) open in the Management console. The live console read the existing single `Personal` Persona and Firefox reported no console errors. Synthetic in-memory facades, run from that installed extension page through the shipped modules, returned 150 ordered Personas; 501 userscript matches and 201 assignments; 150 workflow steps and 150 URLs in one step; 200 batch outcomes; one execution for a duplicate mutating request ID; and a conflict for request-ID reuse with different input. The Integration module returned all 150 Personas over four pages, rejected invalid and changed-snapshot cursors, and completed secret-safe unchanged workflow updates with 200 steps and 500 URLs (3,227–3,229 characters each). No saved Persona or route data was changed; these synthetic checks do not exercise the live background service or Firefox storage APIs.
- **Docs:** `docs/api/management-v1.md`, `docs/api/integration-v1.md`, `docs/reference/compatibility.md`.
- **Compatibility:** v1 wire identifiers retained. Unpaged Integration results above 100 entries now return an explicit `{items, hasMore, nextCursor}` page; small legacy arrays remain. ## F-16 — batch observability and request/rotation correlation

- **Status:** fixed and locally verified for the Phase 03 observations; synthetic Firefox correlation and recovery checks also passed. Live runtime lifecycle acceptance remains open for Phase 08.
- **Root cause:** batch response sanitization discarded result 101+, PCMS mutating `requestId` had no replay semantics, and a second external full-wipe operation could claim an active rotation by Persona UID. A matching active journal without its separate operation record could not resume.
- **Remediation:** one observable batch row per target with `applied` status for oversized successful handlers; five-minute, 32-entry in-memory PCMS mutation replay that refuses new work at capacity; distinct external `operationId`/internal `rotationOperationId`; serialized external rotations by Persona UID; and matching-journal recovery when the operation record is missing. `pcms.batch.completed` remains an advisory totals event; the response carries per-item rows.
- **GitHub commits:** `3cd8e93374fb531e14d1c43f6e16275a683c86a3`, `8fa1735df1164a553d25ad6ce9f04a5591e50cb9`, `79ab08ee01737010cfb6ba0fc5c9ca1af7f6d00f`, `b9f38e0467bd883f56d81a72bc8efd325d5648ce`, `e1b9ce2bd0f38a88915b6050aee55ebaca19066b`.
- **Regression tests:** `pcms-replay.test.mjs`, `pcms-pagination-cardinality.test.mjs`, and `management-integration.test.mjs` exercise concurrent/sequential duplicate IDs, conflict/capacity/expiry, 200 batch rows, mismatched active journals, simultaneous different external rotation IDs, matching-journal resume, and separate external/internal IDs.
- **Browser/native evidence:** the Firefox synthetic Integration harness resumed a matching active rotation journal without a separate operation record or current precondition, kept the external operation ID distinct from the internal rotation ID, and rejected a different external ID claiming the journal. A concurrent pair entered the fake storage service once; the second request received `STATE_CONFLICT` after the first advanced the revision. The PCMS harness also verified duplicate-request replay and conflicting reuse. No destructive Firefox storage call or saved-profile mutation was performed. The repository extension tests and 22 native tests passed.
- **Docs:** `docs/api/management-v1.md`, `docs/api/integration-v1.md`, `docs/reference/compatibility.md`.
- **Compatibility:** the PCMS replay guarantee is boot-scoped and expires five minutes after completion; it cannot promise exactly-once behavior after expiry or restart. New `PCMS_REQUEST_ID_CONFLICT` and `PCMS_REPLAY_CAPACITY` are structured codes. Integration's persisted operation contract remains separate.
- **Residual uncertainty:** real Firefox suspend/wake, browser-storage journal recovery, live rotation timing, and retry after extension lifecycle changes remain Phase 08 gates.
