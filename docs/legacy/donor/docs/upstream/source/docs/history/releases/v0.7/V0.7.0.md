# PersonaMonkey v0.7.0 — Persona OS foundation

v0.7 makes a persona the primary operational object without adding PCMS-specific behavior. Existing routing, native transport, userscript, workflow, cookie-isolation, state-schema, and Gecko-ID contracts remain compatible.

## Dashboard and intelligence

The Profiles page presents responsive cards backed by `persona-platform.js`. A card includes the real Firefox contextual-identity name/icon/color, last use, active tab count, cookie count/bytes, open-origin storage estimate, assigned route, protection state, and the most recent route verification. Route tests are cached only for the current background lifetime and never weaken fail-closed routing.

Card actions are Open, Cookies, Test, Export, Identity, Storage, Duplicate, Backup with cookies, and Delete. The existing routing policy table remains available as the advanced editor.

## Clone and clean reset

Clone choices cover settings, userscripts, workflows, cookies, workflow history, and open tabs. Sensitive and active data are opt-in. Disabling settings also disables route inheritance, so the clone starts on Block.

A full wipe cannot safely use Firefox's global cache clearing. PersonaMonkey instead creates a clean contextual identity with the same visual identity and policy, remaps script/workflow/history references, closes old persona tabs, then removes the old contextual identity. The returned container ID changes; callers must use the returned persona object.

## Storage semantics

Cookie counts and bytes enumerate the complete selected store, including first-party-isolated and dynamically partitioned records. LocalStorage, SessionStorage, IndexedDB, CacheStorage, and `navigator.storage.estimate()` are inspected once per origin currently open in that persona. The UI labels these results as incomplete rather than claiming Firefox exposes a complete container inventory.

`Clear cookies` removes only cookies. `Clear site data` uses `browsingData.remove({cookieStoreId}, {localStorage:true,indexedDB:true})` and clears session/cache data in open persona origins. `Full wipe` uses container rotation as described above.

## Persona package

Files ending in `.persona.personamonkey` are bounded ZIP archives:

```text
manifest.json
persona/settings.json
persona/cookies.json
persona/userscripts/index.json
persona/userscripts/*.user.js
persona/workflows/index.json
persona/metadata.json
```

The format identifier is `persona.personamonkey`, version 1. Exports redact route usernames/passwords. Non-sensitive Export omits cookies; Backup includes them after a plaintext-session warning. Import validates and previews the package, remaps scripts/workflows, reuses only a matching configured route, defaults to Block, and enables Direct only after explicit confirmation.

## PCMS preparation contracts

The frozen facade exposes:

```js
PersonaManager.list()
PersonaManager.open(id)
PersonaManager.export(id)
PersonaManager.duplicate(id, options)
PersonaManager.storage(id)
PersonaManager.clearStorage(id, scope)
PersonaManager.fullWipe(id)
WorkflowRunner.run(id)
Diagnostics.getStatus()
```

Future PCMS work must consume these contracts instead of extension storage or browser internals directly.
