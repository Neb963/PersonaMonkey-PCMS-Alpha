# P405 backup integration — bounded, fail-closed

`index.mjs` composes the P205 `createBackupExporter` instance, P205 `decodeBackupFile`, a background-owned Firefox download service, and an optional **authoritative** Core restore port. Export requires the P205 explicit unencrypted consent. No archive bytes or secrets are returned in UI-facing receipts. The local backup has a plaintext payload; it must never be uploaded or logged.

`downloads.mjs` uses `browser.downloads` and a namespaced durable `browser.storage.local` manifest, saving to `Downloads/PersonaMonkey-PCMS-Alpha-backups/`. Completion is confirmed from browser download history; failed/interrupted/pending entries never displace successful backups. Only previously tracked IDs with verified target paths can be removed. The last `maxComplete` successes are retained. Untracked file IDs are never deleted. The service warns that download history **cannot enumerate arbitrary filesystem files**, even if a bounded history search reports zero unknowns. Call `maintain()` on background startup, alarms and download completion; use one Core-owned instance to serialize access. Browser downloads/history may not be sufficient to remove a known file; treat failures as warnings.

`restore.mjs` binds preview ID+SHA-256 digest to P205's checksum-verified staged archive for 10 minutes. Explicit `RESTORE UNENCRYPTED BACKUP` confirmation is required. Every exported component must be supported by the injected **vetted restore authority**. It must atomically replace Alpha's full records+journal snapshot, durably hold Core before any mutation, coordinate P204 inventory-facts restoration and permitted PersonaMonkey data, and attest binding/session/provider/operation reconciliation before release. On uncertain replacement, it leaves the hold and **never replays** the mutation. Recovery after restart performs reconciliation only. Unsupported sections, including missing PersonaMonkey credentials/sessions, remain explicit.

**Current integration blocker:** P102 storage does not offer an atomic snapshot import/replace operation; P201 Core does not offer a durable restore-specific hold/release interface; PersonaMonkey typed Broker does not provide backup import/export. Those ports are **not implemented here** because they belong to other components and the frozen shared contract. Consequently real restore apply remains `UNSUPPORTED_CAPABILITY` until separately authorized owner changes are merged and wired. Mock authority tests validate coordinator sequencing only; they are not evidence of real restore success or provider-live acceptance. P405 acceptance AP405-02 and GATE-R4 must not be passed on this basis.
