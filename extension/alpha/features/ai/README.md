# P303 — Native Perchance AI review controller

This is a **background-owned task coordinator**, not an AI provider or a new browser automation engine. `createAiSessionController` provides the frozen `aiReview.queue/get/start/recordReview/approveIntent` service interface plus an internal, observation-only `reconnect` operation. The producer must supply the existing P201 Core service boundary and a trusted `native` facade whose commands are executed under PersonaMonkey's Persona/route, control lease, typed execution, and tab budget. It must not supply raw page scripts, direct HTTP, unverified Perchance selectors, or unrestricted `browser.tabs` access. Nothing auto-installs or auto-activates the controller in the P201 bootstrap; production composition belongs to the authorized integration phase.

`createAiIdentity` resolves P102 account/generator binding, a verified account session, and an authoritative P103 Perchance readback. Only an unlisted, account-owned generator with an existing 64-character release identity may enter AI processing. `native.probe` must independently advertise `{authority:'PERSONA_MONKEY',capability:'PERCHANCE_NATIVE_AI',available:true,origin:'https://perchance.org'}`. The existing P103 discovery confirms AI *history* exists, but it does **not** establish a verified native AI-start interface; absent an audited native bridge, `start` fails `UNSUPPORTED_CAPABILITY` **before** any external action. Synthetic test facades provide deterministic coverage only; they are not live provider acceptance.

## Durable session and review boundary

The small `persona-monkey-pcms-alpha-ai` IndexedDB ledger is opened only in a trusted background context. It stores source hashes/revisions, binding epoch, opaque native session ID, dispatch operation ID/phase, and sanitized provenance refs. No code, AI transcript, tokens, cookies, edit keys, or credentials are persisted. A strict IndexedDB transaction and global ledger revision guard each state transition. `RECOVERING`, `ACTIVE`, and `WAITING_HUMAN` consume one account slot by default. `PREPARED` and `DISPATCHING` are committed **before** the native start call; an ambiguous outcome becomes `UNCERTAIN`/`RECOVERING`, never blind replay. `reconnect` is observation-only and requires the same Persona, account, key, binding epoch, session and dispatch operation identity. An unknown session remains on hold. Neither this controller nor its overlay closes tabs.

Native history marked completed does not free a slot. Only an independently verified *saved* source hash and source revision, with trusted provenance, causes a durable `COMPLETED` pending-review record. That record releases the concurrency slot even when awaiting operator approval. An operator approval is a fenced local intent with an exact revision, saved hash, Persona binding and `https://perchance.org/<slug>#edit` origin; it does not save, commit GitHub, change listing, or activate Refresher. P402 is responsible for the separate approval/deployment release transaction.

`extension/alpha/overlay/editor.mjs` exports a compact shadow-DOM overlay for a trusted, future PersonaMonkey-owned injection path. The Perchance origin itself cannot send `PCMS_UI_REQUEST` to P201: `authorizeSender` admits only extension UI pages. A trusted facade must provide `loadContext`, `createOpId`, and `requestApproval`, and both the overlay and the background controller revalidate source/binding; without it, the button is disabled. Reload, hash navigation, stale source, and remote session recovery are explicit states.

**Integration limitation:** This phase cannot modify the existing manifest, P201 bootstrap, P205 exporter, or future P402/P405/P601 functionality. Thus production native helper wiring and overlay injection are intentionally *not* enabled by P303 alone. The P303 AI IndexedDB ledger is not part of P205's frozen Alpha P102 snapshot; P405 must represent its absence explicitly or add an authorized migration/backup contract. Do not describe an archive as a complete AI-session restore meanwhile. No operator-live Perchance or Mullvad behavior has been verified by these deterministic tests.

Test with `node --test tests/alpha/ai/*.test.mjs`. The repository's `node tools/alpha/run-tests.mjs` discovers these tests automatically.
